# Identity and access: API contract

**Status:** Draft for F1, 2026-10-13. The rules are in [access-control.md](../rules/access-control.md), [roles.md](../rules/roles.md) and [catalogs.md](../rules/catalogs.md). This document adds the endpoints and the choices those rules leave open. Endpoint paths follow CYC ([autenticacion.md](../../../CYC/docs/api/autenticacion.md)).

## 1. Every request

| Header | Rule |
|---|---|
| `Authorization: Bearer <token>` | Required on every endpoint except the public ones (health, `auth/login`, `auth/refresh`) |
| `X-Client-Channel: web` or `app` | Required on every endpoint except health. It names where the request comes from. The user must hold `web.access` or `app.access` for it |
| `Accept-Language: es` or `en` | Optional. Spanish by default |

A request is checked in this order. The first failure answers.

| Step | Failure |
|---|---|
| 1. The token is a valid, unexpired access token | `401 UNAUTHENTICATED` |
| 2. The user is active | `403 ACCOUNT_DEACTIVATED` |
| 3. The channel header is `web` or `app` | `400 FORMAT_INVALID` |
| 4. The user holds the channel's permission | `403 INSUFFICIENT_PERMISSIONS` |
| 5. The user does not have a pending password change | `403 PASSWORD_CHANGE_REQUIRED`, except on `auth/me`, `auth/logout` and `auth/change-password` |
| 6. The user holds the endpoint's permission with a scope above `NONE` | `403 INSUFFICIENT_PERMISSIONS` |
| 7. No policy denies the action | `403 POLICY_DENIED` |

Steps 4, 6 and 7 write `ACCESS_DENIED` to the audit log.

**Every endpoint declares its access in the code:** public, any signed-in user, or a permission. The API does not start if an endpoint under `/api/v1` declares none.

## 2. Tokens and passwords

| Subject | Rule |
|---|---|
| Access token | JWT signed with HS256 and the secret `JWT_SECRET` (at least 32 bytes). It carries the user id and nothing else. Lifetime `JWT_ACCESS_MINUTES`, 30 by default |
| Refresh token | 32 random bytes. Only its SHA-256 hash is stored. One use: refreshing returns a new one and revokes the old one. Lifetime `JWT_REFRESH_DAYS`, 30 by default |
| A used, revoked, expired or unknown refresh token | `401 TOKEN_REVOKED` |
| Password | 10 to 72 characters (`PASSWORD_INVALID`). Stored as a BCrypt hash. Never returned, never logged |
| New password equal to the current one | `400 PASSWORD_REUSED` |
| Temporary password | Generated by the API: 14 random characters. Returned **once**, in the response that creates the user or resets the password, as `temporaryPassword`. It is not stored in clear and cannot be read again |
| Wrong username or password | `401 INVALID_CREDENTIALS`. The answer is the same for an unknown user |
| Lockout | The 5th failed login in a row locks the account: `423 ACCOUNT_LOCKED`, until an administrator unlocks it. A successful login resets the count |
| Rate limit | Per IP, in a window of `RATE_LIMIT_WINDOW_MINUTES` (15). Login counts failed attempts only (`RATE_LIMIT_LOGIN_MAX`). Password reset counts every request (`RATE_LIMIT_RESET_MAX`). Over the limit: `429 RATE_LIMITED` |
| Real IP | `TRUSTED_PROXY_HOPS` (0 by default) says how many proxies in front of the API are trusted. With 0, `X-Forwarded-For` is ignored |

**The first administrator, and recovery.** When the API starts and nobody can manage access (a new database, or every administrator locked or deactivated), it gives the user `admin` the role `ADMIN` and the password in `BOOTSTRAP_ADMIN_PASSWORD`, active, unlocked and with a pending password change. While an administrator can sign in, the setting does nothing.

## 3. Endpoints

All under `/api/v1`. "Signed in" means any authenticated user on an allowed channel.

### Session

| Method and path | Access | Body | Response |
|---|---|---|---|
| `POST /auth/login` | Public | `username`, `password` | `token`, `refreshToken`, `user` |
| `POST /auth/refresh` | Public | `refreshToken` | `token`, `refreshToken` |
| `GET /auth/me` | Signed in | | `user` |
| `PATCH /auth/me` | Signed in | `language` | `user`. A person changes their own preferences only |
| `POST /auth/logout` | Signed in | `refreshToken` (optional; without it every session of the user ends) | `204` |
| `POST /auth/change-password` | Signed in | `currentPassword`, `newPassword` | `token`, `refreshToken`. Every earlier refresh token is revoked |

`user` is `{ id, username, name, email, language, mustChangePassword, roles: [key], permissions: { key: scope } }`. `permissions` holds only the scopes above `NONE`.

### Users

| Method and path | Permission | Notes |
|---|---|---|
| `POST /users/query` | `users.view` | Table contract. Filters: `username`, `name`, `email`, `active`, `role`, `lastLoginAt` (range). Sort: `username`, `name`, `email`, `lastLoginAt`, `createdAt` |
| `GET /users/{id}` | `users.view` | |
| `POST /users` | `users.create` | `username`, `name`, `email` (optional), `language` (optional), `roles` (optional; needs `users.permissions` too). Response: `user`, `temporaryPassword` |
| `PATCH /users/{id}` | `users.edit` | `name`, `email`, `language`. Only the fields that are sent change. An empty `email` removes it |
| `DELETE /users/{id}` | `users.delete` | Deactivates. Revokes the user's sessions |
| `POST /users/{id}/reactivate` | `users.delete` | |
| `POST /users/{id}/reset-password` | `users.edit` | Response: `temporaryPassword`. Sets the pending password change and revokes the user's sessions |
| `POST /users/{id}/unlock` | `users.edit` | |
| `PUT /users/{id}/roles` | `users.permissions` | `roles`. Nobody changes their own roles |
| `GET /users/{id}/permissions` | `users.permissions` | The user's exceptions |
| `PUT /users/{id}/permissions/{permission}` | `users.permissions` | `scope`, `reason`, `expiresAt` (optional) |
| `DELETE /users/{id}/permissions/{permission}` | `users.permissions` | |
| `PUT /users/{id}/warehouses` | `users.permissions` | `warehouseIds`: the user's `AREA`. Each one an active warehouse (`CATALOG_VALUE_INVALID`) |

Field rules: `username` 3 to 60 characters, lowercase letters, digits, `.`, `_` and `-`, trimmed and lowercased, unique. `name` 2 to 120 characters. `email` as in [validation.md](../rules/validation.md). `language` is `es` or `en`. `reason` 1 to 500 characters.

### Roles, matrix and policies

All need `roles.manage`, except the permission catalog, which also opens with `users.permissions`.

| Method and path | Notes |
|---|---|
| `GET /permissions` | The permission catalog |
| `GET /roles` | Roles, with how many users hold each |
| `POST /roles` | `key`, `name`. A custom role |
| `PATCH /roles/{key}` | `name`, `active`, `sortOrder`. A system role cannot be renamed or deactivated |
| `DELETE /roles/{key}` | Custom roles only, and only when no user holds it |
| `GET /roles/matrix` | Every cell: `roleKey`, `permissionKey`, `scope` |
| `PUT /roles/matrix` | `changes: [{ roleKey, permissionKey, scope }]`. `NONE` removes the cell. A scope the permission does not support is rejected |
| `GET /policies`, `GET /policies/actions` | Policies, and the action registry with the fields of each action |
| `POST /policies`, `PUT /policies/{key}`, `DELETE /policies/{key}` | `key`, `priority`, `effect`, `action`, `active`, `conditions: [{ field, operator, value }]`, `roles: [key]`. `PUT` replaces the policy: every field except the key is sent again |

A change that leaves no active user holding `roles.manage` through an active role is rejected with `409 ANTI_LOCKOUT`. The check runs in the same transaction as the change.

### Catalogs

| Method and path | Permission | Notes |
|---|---|---|
| `GET /catalogs` | `catalogs.view` | |
| `GET /catalogs/{code}/items` | `catalogs.view` | Active items, in order, with the label of the request's language. `?all=true` adds the inactive ones and every label |
| `POST /catalogs` | `catalogs.manage` | `code` |
| `POST /catalogs/{code}/items` | `catalogs.manage` | `code`, `labels: { es, en }`, `sortOrder` (optional), `attributes` (optional) |
| `PATCH /catalogs/{code}/items/{itemCode}` | `catalogs.manage` | `labels`, `sortOrder`, `active`, `attributes`. The code cannot change |

A label is `{ label, description }`. `label` is 1 to 120 characters. `attributes` accepts only the keys of [catalogs.md](../rules/catalogs.md) section 4, each with its type.

### Audit log

| Method and path | Permission | Notes |
|---|---|---|
| `POST /audit-log/query` | `audit.view` | Table contract. Filters: `action`, `actor`, `targetType`, `targetId`, `occurredAt` (range). Sort: the same five, `occurredAt` by default, newest first |

There is no endpoint to change or delete an audit record, and the database rejects both.

## 4. Audit actions

| Action | When |
|---|---|
| `LOGIN`, `LOGIN_FAILED`, `LOGOUT`, `PASSWORD_CHANGED` | Session events. The password is never recorded |
| `USER_BOOTSTRAPPED`, `USER_CREATED`, `USER_UPDATED`, `USER_DEACTIVATED`, `USER_REACTIVATED`, `USER_PASSWORD_RESET`, `USER_LOCKED`, `USER_UNLOCKED` | User administration |
| `USER_ROLES_CHANGED`, `USER_WAREHOUSES_CHANGED`, `PERMISSION_EXCEPTION_SET`, `PERMISSION_EXCEPTION_REMOVED` | Access of one person |
| `ROLE_CREATED`, `ROLE_UPDATED`, `ROLE_DELETED`, `PERMISSION_MATRIX_CHANGED` | Roles and the matrix |
| `POLICY_CREATED`, `POLICY_UPDATED`, `POLICY_DELETED` | Policies |
| `CATALOG_CREATED`, `CATALOG_ITEM_CREATED`, `CATALOG_ITEM_UPDATED` | Catalogs |
| `ACCESS_DENIED` | A denial by channel, permission or policy. The record carries the permission or the policy key |

## 5. Open questions

1. **Delivery of the temporary password.** The API shows it once to the administrator, who passes it on. There is no email yet. Confirm, or ask for email delivery.
2. **A stolen refresh token.** A refresh token that is used twice is rejected the second time. The API does not end the user's other sessions when that happens. To review in F7.
3. **More than one API instance.** The access cache and the rate limiter live in memory, as in CYC. With several instances they need a shared store. To review in F7.
