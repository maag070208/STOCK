**Progress, 2026-10-14:** F6-01 to F6-05 are done in the API, test first: the current stock report with its totals and the
materials below their minimum (`StockReportTest`), the kardex with the two running balances (`KardexReportTest`), the
movements report (`MovementsReportTest`), the orders and entries reports (`SalesReportTest`) and the XLSX and PDF exports
(`ReportsExportTest`, `ReportsExportServiceTest`), with the unit rules of each in `StockReportRulesTest`,
`KardexRulesTest`, `MovementReportRulesTest` and `SalesReportRulesTest`. The contract is
[reports.md](../../modules/reports.md), and the two open questions were answered by the owner before the work started:
the columns are the ones in that document, and the minimum stock is one number on the material (`products.minimum`,
migration V18). The views the reports read are `stock_movement_rows` (V19) and `order_report_rows` /
`invoice_report_rows` (V20), and the reassignment of an order now keeps its own record (`order_reassignments`, V20).

## F6-01 · Current stock report · API · after F4-06
- Unit (red): the report total equals the sum of the balances it lists; the aisle and rack groups add up to their warehouse.
- E2E (red): after the opening inventory, the total is 10,914,130; a user with `AREA` scope gets totals over their rows only.
- Accept: `reports.view` is required; `reports.export` is checked separately.

## F6-02 · Kardex per product · API · after F4-01
- Unit (red): the running balance after each movement is the previous balance plus or minus the movement; the last running balance equals the current balance.
- E2E (red): a product with an opening, two placements and one pick shows four rows with the right running balance.
- Accept: the kardex lists the movements in order, with the location of each.

## F6-03 · Movements report · API · after F4-01
- Unit (red): the filters by period, type, user and warehouse combine with AND.
- E2E (red): a report for one day and one type returns only those movements.
- Accept: a user outside the scope gets `404` on a warehouse they cannot access.

## F6-04 · Order and invoice reports · API · after F5-07, F4-16
- Unit (red): the order report sums picked and reassigned quantities per status and period.
- E2E (red): the order report for a period returns the picked quantities of its orders; the invoice report returns the discrepancies of its invoices.
- Accept: both use the table contract.

## F6-05 · XLSX and PDF export · API · after F6-01 to F6-04
- Unit (red): the export rows equal the rows of the screen for the same filters.
- E2E (red): the XLSX has the same totals as the screen; exporting writes an audit entry.
- Accept: the file is generated by the API, not in the browser.

## F6-06 · Report screens and kardex screen · Web · after F6-01, F6-02, F6-05
- Unit (red): the kardex table shows the running balance column from the API, and does not compute it.
- E2E (red): Playwright opens the stock report, filters it, exports it, and opens the kardex of one product.
