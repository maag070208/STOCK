# F6: Reports and kardex

**Goal:** the owner can see the stock as it is, see how each material got there, and export the result.

**Depends on:** F4 (movements and balances). Runs in parallel with F5.

**Permissions added:** `reports.view`, `reports.export`.

## Deliverables

### API

- **Current stock.** By warehouse, location and product, with the groups by aisle and rack. Totals always match the sum of balances.
- **Kardex per product.** Every movement of a product in a warehouse, in order, with the running balance per location and in total. The last running balance equals the current balance.
- **Movements report.** By period, type, user and warehouse.
- **Order report.** By status and period, with the picked and reassigned quantities.
- **Invoice and entry report.** By status and period, with the assignments and discrepancies.
- **Products below minimum.** Needs a minimum stock per product, which is not defined yet (see Open questions).
- **Exports.** XLSX and PDF, generated by the API from the same result, and audited. The same approach as CYC's reports ([D-034](../../../CYC/DECISIONES.md)).
- **Permissions:** `reports.view` and `reports.export`, scoped by warehouse (`AREA`) or `ALL`.

### Web

- Report screens with filters and the server-side table contract.
- Kardex screen for one product, with its running balance.
- Export buttons, placed in the page actions.

### App

- None.

## Acceptance criteria

1. The total of current stock equals the sum of the balances, and after the opening inventory it equals 10,914,130.
2. The kardex of a product ends with a running balance equal to its current balance.
3. A user with `AREA` scope sees only their warehouses. Totals in the report are computed over the scoped rows only.
4. The XLSX export has the same totals as the screen.
5. Exporting is audited.
6. A report over a warehouse the user cannot access returns `404`, not an empty list.

## Open questions

Both were answered by the owner on 2026-10-14, before the work started, and they are written down in the contract
([reports.md](../modules/reports.md)):

1. ~~Minimum stock per product~~ Decided: one number on the material, in its unit, `0` when none was set
   (`products.minimum`, migration V18), edited on the material's form. It does not differ by warehouse, and the current
   stock report compares each material's total over the warehouses the reader reaches with it, listing what is missing.
2. ~~Which columns the kardex and the exports carry~~ Decided: the columns of
   [reports.md](../modules/reports.md) section 3, with the file carrying the same columns as the screen.

Still open after F6:

- **Retention of the exported files.** Nothing is kept: a file is built when it is asked for. Whether the owner wants
  them stored is a decision of F7, with the backups.
- **Scheduled reports** (a report sent by itself, daily or weekly) are not in this phase.
