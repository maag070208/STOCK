1. ITThemeProvider
================================================================================
Inyecta dinámicamente variables CSS y clases de Tailwind CSS para soporte de Modo Claro y Oscuro.

### Props (ITThemeProviderProps)
```typescript
export interface ITThemeConfig {
  primaryColor?: string;
  backgroundColor?: string;
  textColor?: string;
  sidebar?: {
    backgroundColor?: string;
    borderColor?: string;
    label?: { color?: string; size?: string; weight?: string };
    icon?: { color?: string; size?: string };
    active?: { backgroundColor?: string; color?: string; iconColor?: string };
    hover?: { backgroundColor?: string };
    badge?: { backgroundColor?: string; color?: string };
  };
  layout?: {
    backgroundColor?: string;
    contentPadding?: string;
  };
}

export interface ITThemeProviderProps {
  theme?: Partial<ITThemeConfig>;
  children: React.ReactNode;
}
```

### Ejemplo Real
```tsx
import React from 'react';
import { ITThemeProvider } from 'axzy-ui-system';

const customTheme = {
  primaryColor: '#6366f1', // Indigo-500
  sidebar: {
    backgroundColor: '#0f172a', // Slate-900 para sidebar oscuro siempre
    borderColor: '#1e293b',
    active: {
      backgroundColor: '#1e1b4b',
      iconColor: '#818cf8',
      color: '#e0e7ff'
    }
  }
};

export default function AppProvider({ children }) {
  return (
    <ITThemeProvider theme={customTheme}>
      {children}
    </ITThemeProvider>
  );
}
```

2. ITLayout
================================================================================
Contenedor principal con soporte para responsive drawer de la barra lateral en tablets y móviles.

### Props (ITLayoutProps)
```typescript
export interface ITLayoutProps {
  topBar: ITTopBarProps;
  sidebar: ITSidebarProps;
  children: React.ReactNode;
  className?: string;
  contentClassName?: string;
  /** `true`: el sidebar ocupa todo el alto y muestra la marca (`topBar.logo` + `topBar.logoText`)
   *  arriba; el topbar cubre solo la columna de contenido y oculta el logo desde `lg`. Default `false`. */
  sidebarFullHeight?: boolean;
}
```

> Aspecto plano: con `<ITThemeProvider appearance="flat">` el layout quita la sombra del sidebar y reserva 248px (en vez de 280px) cuando está expandido. `sidebarFullHeight` es independiente del aspecto y no cambia el layout móvil.

> Nota de layout: en desktop el sidebar está posicionado de forma absoluta y el contenido reserva su ancho en reposo. Con `sidebar.isCollapsed` omitido (default no controlado) o controlado a `true`, reserva 88px y el sidebar se expande sobre el contenido al hacer hover. Si controlas `sidebar.isCollapsed={false}`, reserva 280px para que el sidebar no tape el contenido. No hay prop nueva en `ITLayoutProps`: el ancho se deriva de `sidebar.isCollapsed`.

### Ejemplo Real
```tsx
import React, { useState } from 'react';
import { ITLayout } from 'axzy-ui-system';
import { FaHome, FaUsers, FaCog } from 'react-icons/fa';

export default function AppShell() {
  const [activeTab, setActiveTab] = useState('home');

  const sidebarProps = {
    navigationItems: [
      { id: 'home', label: 'Inicio', icon: <FaHome />, isActive: activeTab === 'home', action: () => setActiveTab('home') },
      { id: 'users', label: 'Usuarios', icon: <FaUsers />, isActive: activeTab === 'users', action: () => setActiveTab('users') },
      { id: 'settings', label: 'Configuración', icon: <FaCog />, isActive: activeTab === 'settings', action: () => setActiveTab('settings') }
    ],
    subitemConnector: 'dot' as const
  };

  const topBarProps = {
    logoText: 'Administración AXZY',
    userMenu: {
      userName: 'Asael Amaro',
      userEmail: 'asael@axzy.dev',
      menuItems: [
        { label: 'Mi Perfil', onClick: () => console.log('Perfil') },
        { label: 'Cerrar Sesión', onClick: () => console.log('Salir') }
      ]
    }
  };

  return (
    <ITLayout topBar={topBarProps} sidebar={sidebarProps}>
      <div className="p-6">
        <h1 className="text-2xl font-bold">Bienvenido al Panel</h1>
        <p className="text-slate-500">Sección activa: {activeTab}</p>
      </div>
    </ITLayout>
  );
}
```

3. ITNavbar
================================================================================
Barra de navegación horizontal con sidebar vertical integrado. Soporta logo, navegación con submenús, menú de usuario colapsable y consume los tokens del theme (`theme.sidebar`, `theme.topbar`, `theme.layout`).

### Props (ITNavbarProps)
```typescript
export interface ITNavigationItem {
  id: string;
  label: string;
  icon?: React.ReactNode;
  action?: () => void;
  isActive?: boolean;
  subitems?: ITNavigationSubItem[];
}

export interface ITNavigationSubItem {
  id: string;
  label: string;
  action: () => void;
  isActive?: boolean;
}

export interface ITNavbarProps {
  logo?: React.ReactNode;
  logoText?: string;
  navigationItems?: ITNavigationItem[];
  userMenu?: {
    userName: string;
    userEmail: string;
    userImage?: string;
    menuItems: Array<{ label: string; onClick: () => void }>;
  };
  children?: React.ReactNode;
  // Legacy (backward compatibility)
  navItems?: React.ReactNode;
  showSidebar?: boolean;
  showSidebarOnMobile?: boolean;
  sidebarItems?: React.ReactNode;
}
```

### Tipos Literales
- `isActive`: `boolean` — marca el item como activo (resaltado con `theme.sidebar.active.*`).
- `subitems`: `ITNavigationSubItem[]` — al hacer click en un item con subitems se expande el submenú en lugar de ejecutar `action`.

### Ejemplo Real
```tsx
import { ITNavbar } from 'axzy-ui-system';
import { FaHome, FaUsers, FaShoppingCart, FaCog } from 'react-icons/fa';

export default function AdminNavbar() {
  return (
    <ITNavbar
      logoText="AXZY Console"
      navigationItems={[
        { id: 'home', label: 'Inicio', icon: <FaHome />, isActive: true },
        { id: 'users', label: 'Usuarios', icon: <FaUsers /> },
        {
          id: 'sales', label: 'Ventas', icon: <FaShoppingCart />,
          subitems: [
            { id: 'orders', label: 'Órdenes', action: () => navigate('/orders') },
            { id: 'invoices', label: 'Facturas', action: () => navigate('/invoices') },
          ],
        },
        { id: 'settings', label: 'Configuración', icon: <FaCog /> },
      ]}
      userMenu={{
        userName: 'Auditor AXZY',
        userEmail: 'auditor@axzy.dev',
        menuItems: [
          { label: 'Ajustes', onClick: () => {} },
          { label: 'Cerrar sesión', onClick: () => {} },
        ],
      }}
    >
      <main className="p-8">Contenido principal</main>
    </ITNavbar>
  );
}
```

4. ITSidebar
================================================================================
Barra lateral reactiva. Soporta colapso automático y varios estilos de líneas conectoras para subítems. Los `subitems` de un item padre aceptan entradas planas o grupos con título (`label` + `items`) que agrupan subítems bajo un encabezado; el título del grupo es solo visual (no es foco, no es clicable y no crea un tercer nivel). Acepta un slot `header` opcional (p. ej. un wordmark) que se renderiza arriba de la navegación y se oculta mientras está colapsada. Cada item acepta `badge` (`number | string`) + `badgeProps` (`ITBadgetProps`) que se renderizan con el átomo `ITBadget`, y el sidebar acepta además `notification` (`ITSidebarNotification`: icono + label + contador `ITBadget`) fijo arriba de la navegación; a diferencia de `header`, la fila de notificación sigue visible al colapsar mostrando solo icono + contador. El riel colapsado se expande automáticamente al pasar el cursor por encima: no hay botón de colapso; su flyout flotante aplana los grupos en una sola lista plana y no dibuja encabezados. Incluye roles/aria para accesibilidad: `nav` etiquetado, toggles con `role="button"` + `aria-expanded`/`aria-controls` + Enter/Space, submenús `role="group"` etiquetados, cada grupo de subítems con su `<ul aria-labelledby>` y subítem activo con `aria-current="page"`.

### Props (ITSidebarProps)
```typescript
export interface ITNavigationSubItem {
  id: string;
  label: string;
  action?: () => void;
  isActive?: boolean;
}

export interface ITNavigationSubItemGroup {
  id: string;                    // clave React + id del encabezado
  label: string;                 // título visible del grupo
  items: ITNavigationSubItem[];  // entradas del grupo (no se anidan grupos)
}

export type ITNavigationSubItemEntry =
  | ITNavigationSubItem
  | ITNavigationSubItemGroup;

export interface ITNavigationItem {
  id: string;
  label: string;
  icon?: React.ReactNode;
  action?: () => void;
  isActive?: boolean;
  subitems?: ITNavigationSubItemEntry[];
  badge?: number | string;        // contenido del ITBadget (ej. contador de notificaciones)
  badgeProps?: ITBadgetProps;     // color/size/variant/className (className para padding)
}

export interface ITSidebarNotification {
  count: number;                  // número dentro del ITBadget
  icon?: React.ReactNode;         // icono a la izquierda (ej. campanita)
  label?: string;                 // aria-label + tooltip (default "Notificaciones")
  onClick?: () => void;
  badgeProps?: ITBadgetProps;     // default { color: "danger", size: "sm" }
}

export interface ITSidebarProps {
  navigationItems: ITNavigationItem[];
  isCollapsed?: boolean;
  /** Reservado por compatibilidad: el componente no tiene botón de colapso (el riel se expande por hover), así que ITSidebar nunca lo invoca. ITLayout lo pasa igualmente. */
  onToggleCollapse?: () => void;
  /** Si es true, el sidebar queda siempre expandido (desactiva el riel colapsado de 88px) y visible en cualquier breakpoint. Default: false. */
  visibleOnMobile?: boolean;
  onItemClick?: (item: ITNavigationItem) => void;
  onSubItemClick?: (subitem: ITNavigationSubItem) => void;
  subitemConnector?: 'dot' | '|' | 'none';
  className?: string;
  /** Contenido opcional renderizado arriba de la lista de navegación (ej. un wordmark). Se oculta al colapsar. */
  header?: React.ReactNode;
  /** Fila de notificación (icono + label + ITBadget) fija arriba de la navegación. Visible también al colapsar (solo icono + contador). */
  notification?: ITSidebarNotification;
  /** Marca (logo + texto) en una fila de 64px arriba del todo. El logo se mantiene al colapsar; el texto no.
   *  `ITLayout` la llena sola con `topBar.logo`/`topBar.logoText` cuando `sidebarFullHeight` está activo. */
  brand?: ITSidebarBrand; // { logo?: ReactNode; text?: string }
  /** `true` (default): el riel colapsado se expande al pasar el cursor. `false`: queda fijo en solo iconos
   *  (el nombre sale en un tooltip) y se abre/cierra con `onToggleCollapse` — en `ITLayout`, el botón de
   *  menú del topbar. Clic en un padre con subitems estando colapsado abre el sidebar con ese grupo. */
  expandOnHover?: boolean;
}
```

> Aspecto plano (`appearance="flat"` en el provider): superficie lisa sin blur ni sombra, 248px de ancho, y el item activo queda como píldora del color primario suave, sin borde, sombra ni barra de acento.

### Ejemplo Real
```tsx
import React, { useState } from 'react';
import { ITSidebar } from 'axzy-ui-system';
import { FaBox, FaCubes } from 'react-icons/fa';

export default function CustomSidebar() {
  const [collapsed, setCollapsed] = useState(false);
  const [activeId, setActiveId] = useState('list');

  const items = [
    {
      id: 'inv',
      label: 'Inventarios',
      icon: <FaBox />,
      isActive: ['list', 'adjust'].includes(activeId),
      subitems: [
        { id: 'list', label: 'Lista Productos', isActive: activeId === 'list', action: () => setActiveId('list') },
        { id: 'adjust', label: 'Ajuste Stock', isActive: activeId === 'adjust', action: () => setActiveId('adjust') }
      ]
    },
    {
      id: 'categories',
      label: 'Categorías',
      icon: <FaCubes />,
      isActive: activeId === 'categories',
      action: () => setActiveId('categories' )
    }
  ];

  return (
    <ITSidebar
      navigationItems={items}
      isCollapsed={collapsed}
      // ITSidebar no renderiza botón de colapso ni invoca onToggleCollapse:
      // el riel colapsado se expande solo al pasar el cursor por encima.
      subitemConnector="dot" // Prueba con 'dot', '|', o 'none'
      // Slot opcional arriba de la navegación; se oculta al colapsar.
      header={<span className="text-xs font-bold tracking-wide">AXZY v1.3</span>}
      className="h-screen"
    />
  );
}
```

```typescript
export interface ITTopBarProps {
```

7. ITInput
================================================================================
Campo de texto con soporte nativo para etiquetas de error dinámicas y validación automática `onBlur` en requeridos.

### Props (ITInputProps)
```typescript
export interface ITInputProps {
  name: string;
  type?: 'text' | 'password' | 'number' | 'email' | 'textarea' | 'checkbox';
  label?: string;
  placeholder?: string;
  value?: any;
  onChange: (e: React.ChangeEvent<HTMLInputElement | HTMLTextAreaElement>) => void;
  onBlur?: (e: React.FocusEvent<HTMLInputElement | HTMLTextAreaElement>) => void;
  variant?: 'primary' | 'secondary' | 'success' | 'danger' | 'warning' | 'info';
  iconLeft?: React.ReactNode;
  error?: string | boolean;
  required?: boolean;
  disabled?: boolean;
  className?: string;
}
```

### Ejemplo Real
```tsx
import React, { useState } from 'react';
import { ITInput } from 'axzy-ui-system';
import { FaEnvelope } from 'react-icons/fa';

export default function EmailInput() {
  const [email, setEmail] = useState('');
  const [error, setError] = useState<string | boolean>('');

  const validate = () => {
    if (!email) {
      setError('Este campo es requerido');
    } else if (!/\S+@\S+\.\S+/.test(email)) {
      setError('Correo electrónico inválido');
    } else {
      setError('');
    }
  };

  return (
    <ITInput
      name="email"
      type="email"
      label="Correo Electrónico"
      placeholder="ejemplo@axzy.dev"
      value={email}
      iconLeft={<FaEnvelope />}
      onChange={(e) => {
        setEmail(e.target.value);
        if (error) setError(''); // Limpia error al escribir
      }}
      onBlur={validate}
      error={error}
      required={true}
    />
  );
}
```

================================================================================
Selector desplegable nativo con soporte para validación, etiquetas y adaptabilidad a temas oscuros.

### Props (ITSelectProps)
```typescript
export interface ITSelectOption {
  label: string;
  value: string | number;
}

export interface ITSelectProps {
  name: string;
  label?: string;
  value?: string | number;
  options: ITSelectOption[];
  onChange: (e: React.ChangeEvent<HTMLSelectElement>) => void;
  onBlur?: (e: React.FocusEvent<HTMLSelectElement>) => void;
  error?: string | boolean;
  required?: boolean;
  disabled?: boolean;
  placeholder?: string;
  className?: string;
}
```

### Ejemplo Real
```tsx
import React, { useState } from 'react';
import { ITSelect } from 'axzy-ui-system';

export default function CountrySelector() {
  const [country, setCountry] = useState('');
  const [error, setError] = useState<string | boolean>('');

  const options = [
    { label: 'México', value: 'MX' },
    { label: 'Estados Unidos', value: 'US' },
    { label: 'España', value: 'ES' }
  ];

  return (
    <ITSelect
      name="country"
      label="País de Residencia"
      placeholder="Selecciona un país"
      options={options}
      value={country}
      required={true}
      onChange={(e) => {
        setCountry(e.target.value);
        setError('');
      }}
      onBlur={() => {
        if (!country) setError('Debe seleccionar un país');
      }}
      error={error}
    />
  );
}
```

### Guía de layout, densidad y virtualización

- `layout="auto"` (default) mantiene `min-w-max`: el ancho de las columnas puede reajustarse al entrar/salir contenido durante el scroll vertical. `layout="fixed"` respeta `width` por columna y elimina `min-w-max` y el piso `min-w-[150px]` del header.
- `density` controla padding y alto de fila. El alto asumido por defecto se calcula con `getRowHeight(size, density)` = padding vertical de celda + line box del `size` + 1px del `divide-y`. Baseline `size="md"` (line box `text-sm` = 20px): compact = 33px (`px-3 py-2` header / `px-3 py-1.5` cell), normal = 45px (`px-4 py-4` / `px-4 py-3`), comfortable = 53px (`px-4 py-5` / `px-4 py-4`).
- `size` cambia el font-size (`text-xs|sm|lg`) y con ello el line box (sm 16 / md 20 / lg 28 px), desplazando el alto asumido: sm −4 / md 0 / lg +8 px. Matriz completa de `getRowHeight(size, density)` (filas = density, columnas = size):

  | density \ size | sm (16px) | md (20px) | lg (28px) |
  |----------------|-----------|-----------|-----------|
  | compact        | 29        | 33        | 41        |
  | normal         | 41        | 45        | 53        |
  | comfortable    | 49        | 53        | 61        |

  El alto asumido es EXACTO solo para celdas de UNA línea. Una celda de dos líneas (avatar + texto) mide ~50px real y desalinea los spacers de la virtualización.
- `autoCardBreakpoint`: cae a la vista cards cuando el CONTENEDOR (no el viewport) mide menos que el valor en px. Mientras está forzado, el toggle "Table" queda deshabilitado y "Cards" sigue habilitado. `0` desactiva. Como la vista cards nunca se virtualiza, `autoCardBreakpoint` desactiva `virtualized` en silencio al dispararse: NO combinar `virtualized` + `autoCardBreakpoint`.
- `virtualized`: renderiza solo la ventana visible de filas con spacer rows que preservan la altura total. Aplica SOLO a la vista tabla; la vista cards NUNCA se virtualiza. El toggle interno Table/Cards también desactiva la virtualización al pasar a cards.

### Receta para eliminar el scroll horizontal

```tsx
<ITTable
  columns={[
    { key: 'name',  label: 'Nombre', type: 'string', width: '28%', truncate: true },
    { key: 'email', label: 'Email',  type: 'string', width: 220,    truncate: true },
    { key: 'role',  label: 'Rol',    type: 'string', width: 140,    align: 'center' },
  ]}
  data={data}
  layout="fixed"     // respeta width y quita min-w-max / min-w-[150px]
  density="compact"  // reduce padding y alto de fila
/>
```
Pasos: (1) `layout="fixed"`, (2) `width` en cada columna (number = px; string = cualquier longitud CSS, ej. `"20%"`, `"12rem"`), (3) `truncate` en columnas de texto largo (agrega ellipsis y `title` nativo con el valor string/number), (4) `density` para compactar. El `<colgroup>` solo se emite si al menos una columna define `width`.

### Columnas fijas (pinned)

`Column.pinned: 'left' | 'right'` (opt-in; omitirlo produce un render idéntico al anterior) congela una columna al borde indicado mientras la tabla hace scroll horizontal. Se implementa con `position: sticky`, así que la celda permanece visible aunque el wrapper use `overflow-x-auto`; no hace falta marcar el contenedor como `relative`.

```tsx
<ITTable
  columns={[
    { key: 'name',   label: 'Nombre', type: 'string',  width: 200, pinned: 'left'  },
    { key: 'email',  label: 'Email',  type: 'string',  width: 280, truncate: true  },
    { key: 'role',   label: 'Rol',    type: 'string',  width: 180, truncate: true  },
    { key: 'status', label: 'Estado', type: 'boolean', width: 120, pinned: 'right' },
  ]}
  data={data}
  layout="fixed"
  density="compact"
/>
```

- Los offsets sticky se acumulan en px desde el `width` de cada columna pinneada previa del MISMO lado (izquierda en orden de render; derecha en orden inverso). Una columna cuyo `width` no sea px (p. ej. `"20%"`, `"12rem"`) aporta `minWidth ?? 0`, así que declara `width` en px en todas las columnas pinneadas de un mismo lado para evitar solapamiento.
- Contrato soportado/probado: UNA columna pinneada por lado. Los offsets múltiples se calculan (ver arriba) pero varias columnas por lado no están cubiertas por las pruebas.
- La celda pinneada pinta fondo opaco (`--color-table-rowBg`; `--color-table-rowHover` en hover, sincronizado con el hover de la fila) y un separador de 1px hacia el contenido desplazable (`.it-table-pinned-left` / `.it-table-pinned-right`).
- Z-index: header pinneado `z-[15]`, header sticky normal `z-10`, celda de cuerpo pinneada `z-[1]`. El overlay de carga de ITDataTable (`z-20`) queda por encima de todos.
- Compone con `stickyHeader` y `virtualized`: el header pinneado hereda el fondo del header (`--color-table-headerBg`) y el z-index descrito arriba.
- `layout="fixed"` + `width` en px es la combinación recomendada para que una columna pinneada de `type: 'actions'` no se encoja.
- Limitación conocida: en la variante `striped`, el tinte de la franja de fila par queda cubierto por el fondo opaco de la celda pinneada de esa columna.

### Filtros de columna

`Column.filter` selecciona el control renderizado en el header de la columna:

| filter           | Control          | Fuente / valor guardado                                      |
|------------------|------------------|--------------------------------------------------------------|
| `true`           | `ITInput`        | texto/número (o toggle si `type: "boolean"`)                 |
| `"catalog"`      | `ITSelect`       | `catalogOptions.data`; guarda el `id` seleccionado           |
| `"search"`       | `ITSearchSelect` | `catalogOptions.data`; guarda el `value` (id) exacto         |
| `"date"`         | `ITDatePicker`   | `Date` único                                                 |
| `"date-range"`   | `ITDatePicker`   | tupla `[Date \| null, Date \| null]`                         |

Notas:

- `"search"` usa búsqueda local sobre `catalogOptions.data`. Para búsqueda en servidor, define `catalogOptions.onSearch(query)`; el `ITSearchSelect` delega el filtrado a ese callback (debounced) y el padre debe actualizar `data`.
- `"date"` y `"date-range"` aceptan `dateFilterOptions: { minDate?, maxDate? }`, reenviado al `ITDatePicker` como límites de selección.
- Un rango con ambos extremos `null` se considera "sin filtro" y se elimina del mapa de filtros.
- En `ITTable` el filtrado es local: `"date"` compara por día (`isSameDay`) y `"date-range"` incluye el día completo de `start` y `end` (`startOfDay` / `endOfDay`).
- En `ITDataTable` el filtro viaja en `fetchData(params)`: `params.filters[key]` es `Date` para `"date"`, `[start, end]` para `"date-range"`, o el escalar/id para el resto.
- Los tipos `ColumnFilterMode`, `ColumnFilterValue` y `ColumnFilters` se exportan desde `@axzydev/axzy_ui_system`.

### Virtualización: cuándo usarla y límites

- Rinde SOLO con un page size grande. Los defaults (`defaultItemsPerPage=10`, `itemsPerPageOptions=[5,10,20]`) son demasiado chicos: subir ambos (ej. 300) para notar la diferencia.
- Las filas asumen alto UNIFORME (`rowHeight`, default `getRowHeight(size, density)`). Baseline `size="md"` = compact 33 / normal 45 / comfortable 53; `size` lo desplaza por el line box (sm −4 / md 0 / lg +8), es decir sm 29/41/49 · md 33/45/53 · lg 41/53/61. Contenido que hace wrap rompe el cálculo: usar `truncate` + `layout="fixed"`. El asumido es exacto solo para celdas de una línea; una celda de dos líneas (avatar + texto) mide ~50px real y desalinea los spacers.
- `virtualizedMaxHeight` (default 400) es el alto del contenedor con scroll; `overscan` (default 5) son las filas extra arriba/abajo; `stickyHeader` (default false) fija los `<th>` usando el token `--color-table-headerBg` (fallback `#f8fafc`). Las tres solo aplican con `virtualized`.
- El scroll se reinicia al cambiar página o items-per-page (`resetKey = página-itemsPerPage`), pero NO al cambiar filtros (limitación conocida y aceptada).
- `aria-rowcount` refleja la página actual (+1), no el dataset completo, porque la paginación es independiente.
- A11y al virtualizar: `<table aria-rowcount={filas+1}>`, header `<tr aria-rowindex={1}>`, filas `aria-rowindex={absoluto+2}`, spacers `aria-hidden="true"`.
- `TableDensity` se exporta desde `src/index.ts`. Los hooks `useVirtualRows` y `useElementSize` son internos y NO se exportan. `getRowHeight` y `sizeLineHeights` (junto con `densityStyles` y `tableAlignClasses`) también son internos: se exportan desde `src/types/table.types.ts` pero NO desde `src/index.ts`.

Nota de paridad: ITSearchTable NO fue modificado; no tiene `layout`, `density`, `autoCardBreakpoint`, `virtualized` ni `width` por columna.

Drift conocido (no corregido en código): `ITTableProps.className` está declarado pero NO se aplica en `table.tsx` (usar `containerClassName`). `ITDataTableProps.debounceMs` tiene JSDoc `@default 400` pero el valor real en `dataTable.tsx` es `500`.

```typescript
  virtualizedMaxHeight?: number;                 // default 400; alto max del contenedor con scroll
```

### Guía de layout, densidad y virtualización

ITDataTable comparte exactamente las mismas props de configuración que ITTable (ver §16 para el detalle completo): `layout` (`'auto'` default | `'fixed'`), `density` (`'compact' | 'normal' | 'comfortable'`, default `'normal'`), `autoCardBreakpoint` (px, default `0`), `virtualized` (default `false`), `virtualizedMaxHeight` (default `400`), `rowHeight` (default `getRowHeight(size, density)`, size-aware), `overscan` (default `5`) y `stickyHeader` (default `false`). `Column<T>` también acepta `width` / `minWidth` / `align` / `truncate` / `pinned` (`'left' | 'right'`, default sin congelar).

Receta anti-scroll-horizontal: `layout="fixed"` + `width` por columna + `truncate` en texto largo + `density` para compactar. `width` number = px, string = longitud CSS. El `<colgroup>` solo se emite si alguna columna define `width`. Para congelar columnas al borde durante el scroll horizontal usa `Column.pinned: 'left' | 'right'` (ver §16, "Columnas fijas (pinned)").

Virtualización (solo vista tabla; cards nunca virtualiza): rinde solo con un page size grande (`defaultItemsPerPage` + `itemsPerPageOptions` altos; los defaults 10/[5,10,20] no bastan). En ITDataTable (server-side) la ventana se calcula sobre la PÁGINA ACTUAL (`data.length`), NO sobre `total`: con un page size chico el efecto es invisible porque la página entera cabe en el viewport. Filas de alto uniforme (`rowHeight`, default `getRowHeight(size, density)` size-aware: sm 29/41/49 · md 33/45/53 · lg 41/53/61; exacto solo para celdas de una línea); usar `truncate` + `layout="fixed"`. El scroll se reinicia al cambiar página o items-per-page, NO al cambiar filtros. `aria-rowcount` refleja la página actual (+1), no el dataset. `useVirtualRows` / `useElementSize` son hooks internos NO exportados; `getRowHeight` / `sizeLineHeights` también son internos; `TableDensity` sí se exporta.

Nota de paridad: ITSearchTable NO fue modificado; no tiene `layout`, `density`, `autoCardBreakpoint`, `virtualized` ni `width` por columna.

```tsx
}
```

```tsx
        { id: 'edit', label: 'Editar', icon: <FaEdit />, onClick: () => edit() },
        { id: 'delete', label: 'Eliminar', icon: <FaTrash />, danger: true, divider: true, onClick: () => remove() },
      ]}
    />
  );
}
```

### Notas
- Teclado: `ArrowUp`/`ArrowDown` navegan, `Enter`/`Space` activan, `Esc` cierra, `Home`/`End` saltan.
- Usa `role="menu"` / `role="menuitem"` y `aria-haspopup` / `aria-expanded` en el trigger.

42. ITMultiSelect
================================================================================
Selector de múltiples valores con dropdown buscable, chips removibles y
navegación por teclado. Soporta filtrado local y búsqueda remota (`onSearch`),
resumen colapsado de chips (`maxVisibleChips`) y plantilla de opción
personalizada (`renderOption`). El dropdown va en portal (no se recorta).

### Props (ITMultiSelectProps)
```typescript
export interface ITMultiSelectOption {
  label: string;
  value: string | number;
  [key: string]: any;
}

export interface ITMultiSelectProps {
  name?: string;
  label?: string;
  placeholder?: string;           // default "Selecciona opciones"
  options: ITMultiSelectOption[];
  value: (string | number)[];     // controlado
  onChange?: (values: (string | number)[], options: ITMultiSelectOption[]) => void;
  onBlur?: (e: React.FocusEvent<HTMLInputElement>) => void;
  valueField?: string;            // default "value"
  labelField?: string;            // default "label"
  disabled?: boolean;
  readOnly?: boolean;
  required?: boolean;
  touched?: boolean;
  error?: string | boolean;
  size?: 'sm' | 'md' | 'lg';      // default "md"
  maxVisibleChips?: number;       // default 3
  clearable?: boolean;            // default true
  searchable?: boolean;           // default true
  onSearch?: (query: string) => void;
  isLoading?: boolean;
  noResultsMessage?: string;
  renderOption?: (option: ITMultiSelectOption, state: { isSelected: boolean; searchTerm: string }) => React.ReactNode;
  className?: string;
}
```

### Ejemplo Real
```tsx
import { useState } from 'react';
import { ITMultiSelect } from 'axzy-ui-system';

export default function SkillsPicker() {
  const [selected, setSelected] = useState<(string | number)[]>(['react']);

  return (
    <ITMultiSelect
      label="Skills"
      options={[
        { value: 'react', label: 'React' },
        { value: 'ts', label: 'TypeScript' },

      ]}
      value={selected}
      onChange={(values) => setSelected(values)}
      maxVisibleChips={3}

  );
}
```

### Notas
- Teclado: `ArrowUp`/`ArrowDown` navegan, `Enter` alterna, `Backspace` quita el último chip, `Esc` cierra.
- `role="combobox"` + `role="listbox"` (`aria-multiselectable`) para accesibilidad.
- El dropdown va en portal, así que no se recorta dentro de ITCard.

================================================================================
44. ITMaskedInput
================================================================================
Input con máscara de formato. El usuario solo escribe los caracteres útiles y
los separadores se insertan solos. `value` y `onChange` trabajan con el valor
limpio (raw), sin separadores ni caracteres de relleno.

### Tokens de la máscara
| Token | Acepta                            | Guarda      |
|-------|-----------------------------------|-------------|
| `9`   | un dígito                          | tal cual    |
| `A`   | una letra                          | MAYÚSCULA   |
| `a`   | una letra                          | tal cual    |
| `x`   | alfanumérico                       | tal cual    |
| `*`   | cualquier carácter                 | tal cual    |
| otro  | literal separador auto-insertado   | no aplica   |

Ejemplos de máscara: `xxxx-xxxx-xxxx`, `(999) 999-9999`, `9999-9999-9999-9999`,
`99999`, `A-A-A-999`.

### Props (ITMaskedInputProps)
```typescript
export interface ITMaskedInputProps {
  name: string;                        // Nombre del campo
  mask: string;                        // Patrón (tokens + literales)
  value?: string;                      // Valor limpio (raw)
  onChange: (e: { target: { name: string; value: string } }) => void; // e.target.value = raw
  onBlur?: (e: React.FocusEvent<HTMLInputElement>) => void;
  onComplete?: (value: string) => void; // Dispara al llenar toda la máscara
  pattern?: RegExp;                    // Validación full-match del raw en blur
  placeholderChar?: string;            // Relleno de slots vacíos (default "_")
  variant?: 'primary' | 'secondary' | 'success' | 'danger' | 'warning' | 'info' | 'purple' | 'gray';
  size?: 'sm' | 'md' | 'lg';           // default "md"
  label?: string;
  disabled?: boolean;
  required?: boolean;
  touched?: boolean;
  error?: string | boolean;
  className?: string;
  containerClassName?: string;
  iconLeft?: ReactNode;
  iconRight?: ReactNode;
  autoFocus?: boolean;
}
```

### Ejemplo Real
```tsx
import { useState } from 'react';
import { ITMaskedInput } from 'axzy-ui-system';

export default function ActivationCode() {
  const [code, setCode] = useState('');

  return (
    <ITMaskedInput
      name="activation_code"
      label="Código de activación"
      mask="xxxx-xxxx-xxxx"
      value={code}
      onChange={(e) => setCode(e.target.value)}
    />
  );
}
```

### Ejemplo con validación regex y onComplete
```tsx
import { useState } from 'react';
import { ITMaskedInput } from 'axzy-ui-system';

export default function PhoneField() {
  const [phone, setPhone] = useState('');

  return (
    <ITMaskedInput
      name="phone"
      label="Teléfono"
      mask="(999) 999-9999"
      pattern={/^\d{10}$/}
      onChange={(e) => setPhone(e.target.value)}
      onComplete={(v) => console.log('Teléfono completo:', v)}
    />
  );
}
```

### Notas
- El cursor se conserva al editar en medio de la máscara (incluye borrado de separadores).
- `pattern` valida contra el raw completo; mensaje genérico "Formato inválido" salvo que se pase `error` como string.
- `onComplete` es útil para tarjetas, CVV u OTP.

================================================================================
45. ITInputNumber
================================================================================
Campo numérico especializado: es un `ITInput` (misma label, validación, tamaños
e iconos) que SIEMPRE aplica formato de moneda (separador de miles + decimales
fijos) y emite un `number` real en `onChange`/`onBlur` en lugar de un string.

### Props (ITInputNumberProps)
```typescript
export interface ITInputNumberProps {
  name: string;                                          // requerido
  value?: number | null;                                 // valor numérico
  onChange: (value: number | undefined, event: React.ChangeEvent<HTMLInputElement>) => void; // requerido
  onBlur?: (value: number | undefined, event: React.FocusEvent<HTMLInputElement>) => void;
  decimals?: number;                                     // Default: 2 (0 = enteros)
  prefix?: string;                                       // ej. "$" (se ignora si hay iconLeft)
  label?: string;
  placeholder?: string;
  min?: number;                                          // clamp al salir del campo
  max?: number;                                          // clamp al salir del campo
  size?: 'sm' | 'md' | 'lg';                             // Default: 'md'
  disabled?: boolean;                                    // Default: false
  readOnly?: boolean;                                    // Default: false
  required?: boolean;                                    // Default: false
  touched?: boolean;
  error?: string | boolean;                              // true = mensaje genérico
  iconLeft?: React.ReactNode;
  iconRight?: React.ReactNode;
  containerClassName?: string;
  labelClassName?: string;
  className?: string;
  autoFocus?: boolean;                                   // Default: false
  focusContent?: boolean;                                // Default: false
  onKeyDown?: (event: React.KeyboardEvent<HTMLInputElement>) => void;
}
```

### Valores literales
- `decimals`: cualquier entero >= 0. `0` = solo enteros, `2` = centavos (default).
- `size`: `'sm'` | `'md'` | `'lg'`.
- `error`: `true` (mensaje genérico "Este campo es requerido") o `string` (mensaje propio).

### Ejemplo Real
```tsx
import { useState } from 'react';
import { ITInputNumber } from 'axzy-ui-system';

export default function AmountField() {
  const [amount, setAmount] = useState<number | null>(null);
  const [qty, setQty] = useState<number | null>(1);

  return (
    <>
      <ITInputNumber
        name="amount"
        label="Monto"
        placeholder="0.00"
        prefix="$"
        value={amount}
        onChange={(value) => setAmount(value)}   // value: number | undefined
        min={0}
        max={100000}
      />

      <ITInputNumber
        name="qty"
        label="Cantidad (enteros)"
        decimals={0}
        min={1}
        max={99}
        value={qty}
        onChange={(value) => setQty(value)}
      />
    </>
  );
}
```

### Notas
- `onChange` entrega un `number` ya parseado (o `undefined` si el campo está vacío); no hace falta `parseFloat`.
- Formatea al perder el foco (miles + decimales) y muestra el número crudo mientras se escribe.
- `min`/`max` se aplican al salir del campo (clamp) y también bloquean dígitos que excedan el máximo al teclear.
- Internamente usa `ITInput` con `currencyFormat` + `formatNumber`, por lo que hereda el tema y los estados de error.
- `prefix` es un atajo de `iconLeft`; para cualquier nodo personalizado usa `iconLeft` directamente.
